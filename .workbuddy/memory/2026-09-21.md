## ★ 新发现：后端 CORS 回显 Origin → 可以本地起站当临时入口

```
OPTIONS /api/deepseek  Origin: http://localhost:5173
→ 204  access-control-allow-origin: http://localhost:5173
       access-control-allow-methods: POST
       access-control-allow-headers: Content-Type
POST 同 Origin → 200 且同样回显
```

**CORS 是回显 Origin（不是固定白名单）**，所以前端可以本地跑、后端照常连。
实测本地静态服务：`index.html` 与 8 个前端文件全部 200（脚本引用都是相对路径 `./`，
只有 CloudBase SDK 走 CDN）。

```bash
cd /Users/emobcccz/Documents/GitHub/math-practice-demo
python3 -m http.server 8099 --bind 127.0.0.1   # 然后开 http://127.0.0.1:8099
```

★ **通用套路**：「线上前端挂了、后端还活着」时，先测一下后端 CORS 是否回显 Origin。
回显就能立刻用本地静态服务恢复一个可用入口（练习主流程可用；云同步/登录可能受
CloudBase 侧白名单限制，但本地存储仍在）。这比等托管修好快得多。

**网关拼接规则（探针反推，数据自洽）**：`key = calcdaily/ + <请求路径（含前导斜杠）>`

```
/index.html        → calcdaily//index.html
/calcdaily/index.html → calcdaily//calcdaily/index.html
```

每个键都多一个斜杠 → COS `NoSuchKey` → 全部 404。

**修法**：先看「云存储」里文件在根目录还是 `calcdaily/` 下；大概率把 **部署路径 `/calcdaily` → `/`**，
