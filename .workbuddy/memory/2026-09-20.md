## 50 题线上 smoke：第一轮跑崩，是**工具 bug**不是线上问题

`npm run smoke -- --label online-50` 出题阶段 50/50 跑完（成功 31、失败 19），

ReferenceError: WRONG_PROBES is not defined

**根因**：`run.mjs` 里写的是

```js
export { WRONG_PROBES, VALID_PROBES, probesFor, rhsOf } from './probes.mjs';
import { probesFor } from './probes.mjs';
```

前一行是**再导出**，ESM 里 `export … from` **不会**在本模块创建绑定；
正文用 `WRONG_PROBES` / `VALID_PROBES` 就直接 ReferenceError。
——从 Task #4 把探针组挪进 `probes.mjs` 那天起，**判题阶段就没跑通过**，
而一直没人发现，因为它是**第一次真正打线上端到端跑**。

**为什么原有守卫没抓到**：`tests/smoke-matrix.cjs` 是
`await import('run.mjs')` 之后读**模块导出**——那条路走的正是再导出、是通的。
出问题的是模块**内部**的本地绑定。**守卫验的是导出面，bug 在内部绑定上。**

**修复**：`import { WRONG_PROBES, VALID_PROBES, probesFor } from './probes.mjs';`
（保留那行再导出给既有守卫用），并加了一条**静态守卫**：
剥掉注释与 `export {…} from` 之后，凡 `probes.mjs` 导出、且正文用到的名字，
必须在一条真正的 `import` 里。
已用「还原成坏版本」验证过守卫有牙齿（准确报出 `VALID_PROBES, WRONG_PROBES`）。

## 独立数学复核：18/18 正确（真·独立，不是引用 gate）

`tools/smoke/verify.mjs` **自己声明了局限**：它的 oracle 与服务端是**同一份引擎**，
证明的是"闸门执行了、结果没被篡改"，**不是"换个人重算一遍"**。
用户明确要求不能把 VERIFIED 直接当成正确 → 另写**纯 Python 数值验证器**
（`.workbuddy/smoke/2026-09-20T07-28-20-online-50-v2/independent-review/`）：

- 5 个极限：mpmath **50 位精度** + 内置 `limit` → **5/5 精确命中，相对误差 0.00e+00**
- 2 个二阶导数：数值二阶中心差分 → 2/2
- 7 个不定积分：对声称原函数求数值导比对被积函数 → 7/7
- 3 个定积分：Simpson → 3/3

**合计 17 项检查（覆盖 18 题）全过。**

**两个假阴性教训（重要）**：
1. float64 算极限会因**灾难性相消**把正确答案算成 0
   （`(cos x − e^{−x²/2})/x⁴` 在 x=1e-4 时 x⁴=1e-16，分子差丢光有效位）。
   **数值复核极限必须用高精度算术**（mpmath）。
2. `(tan x − x)/(x²ln(1+x))` 误差按 10 倍**线性**下降 → 是一阶 O(x) 修正项，
   不是不收敛。解析展开 `(1/3)(1 + x/2 + O(x²))` 与数值一致。
   **别把"收敛慢"当成"答案错"。**

## ★ 独立复核第一次抓出「穿过闸门的错题」

`y=\left(\frac{x^2+1}{x^2-1}\right)^{\arctan x}`，**同一道题面在两个不同轮次各错一次，错法还不一样**：

- `r1x` 答案缺 `arctan x` 因子（相对误差 0.022–0.398）
- `r2` 答案符号反了（`+4x·arctan x/(x⁴−1)` 应为 `−`，相对误差 0.688–2.508）
- 正确答案 `y'=u^{arctan x}[ln u/(1+x²) − 4x·arctan x/(x⁴−1)]`（相对误差 1e-81）

**修正了上一轮的判断**：上一轮写的是"2 道错题是同一处错误的重复"——**错了**，
是同一道题的**两个不同错误**。裁决方法：mpmath 80 位直接对 y 求数值导当基准，不采信任何解析式。

**闸门 / `verify.mjs` / reviewer 都没拦住**（符号+对数求导是共同盲点，解析与答案还互相自洽，
所以 `SOLUTION_MISMATCH` 也不响）。

**但判题侧留下了干净信号**：5 轮 × 10 题 × 3 次 = 150 条判词里，
只有 **3 条 `uncertain`**，**全部属于这道错题**（`method=['ai']`，`reason=['judge_uncertain']`）。
→ **`judge_uncertain` 是近乎零噪声的"这题可疑"信号**，本轮零误伤。

**两个模块的病完全不同**：
- derivative 是「**形状不可验证**」（生成器写出闸门读不懂的题面），不是算错
- integral 题面永远可验证，但「**答案算错**」（`UNVERIFIED_SHAPE` = 0）

derivative 20 个格里 **11 个在 4 轮里从未放行过一次**（整片格子是空的）。
